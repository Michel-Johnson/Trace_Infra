# Trace Hunter Roadmap

更新：2026-09-20。按可验收成果推进。后端第一阶段已收敛到 001–020；后续不会以新增轮数或更换语言作为完成标准。

平台持续建设中性的记录、版本、存储、检索、切片和回放能力。业务方通过插件定义分类、评价、训练选择与视图。本文是工作顺序，勾选以实际发布与验收为依据。

## 当前交付与下一步贯通

- [x] **一个清楚的产品入口。** `/about.html` 与 `/research.html` 说明轨迹如何流转、多个业务视角以及能力边界；见[本次交付](project/release-20260914.md)。
- [ ] **一个明确的协议范围。** 固定采集端与后端共同接受的版本、特性和示例。相同 Schema 标识不能暗示双方支持不同字段；草案输入给出明确支持范围及错误，不静默丢字段。
  - 当前已提供 `/api/v1/trace-formats`，返回固定 profile 与 Schema 摘要。采集草案新字段的兼容升级仍待联调，不自动纳入本次发布。
- [x] **一次可复核的核心发布。** Web / API / Worker 运行发布的提交，数据库追加迁移、内容目录与凭据配置正确；原数据摘要不变，重启后能读取已有内容与结果，回退代码不覆盖更新的数据。0d0148e 发布已保存部署版本与验证结果；后续前端版本单独记录。
- [ ] **一份业务报告走完正式接口。** 选择已有轨迹，显式运行或接入一个业务插件，将结果保存为固定输入的产物，在 Case 展示“结论 → 证据 → 原始调用”；重复提交不重复结果。
  - 已提供[最小原型与设计](prototypes/trace-analysis-mvp/design.md)：六个组件、物业因果分析示例、伪代码及合成输入/预期输出。真实插件接入与实验仍待验收，不计作正式分析功能上线。
- [ ] **人和 Agent 读到同一份结果。** 网页与远程客户端使用相同输入 / 结果版本；读取缺失分析返回缺失状态，不能暗中发起模型调用。
- [x] **一套能贯穿现有后端的 Case。** 28 项可执行 Case 覆盖导入、对比、标签与证据、附件、长轨迹、分页、故障恢复及三个业务统计示例，SQLite/PostgreSQL 均通过；另列 9 个未运行目标，见[最新报告](reports/platform-case-coverage-20260920.md)。网页、Sancho、连接器和回放另行验收。

发布验收同时覆盖：原有登录与插件流程仍可用、批量 / Case 统计范围一致、没有运行中的任务或原件在迁移时丢失。依赖继续使用固定锁文件和七天冷却规则，详见[部署](deployment.md)与[依赖管理](security/dependencies.md)。

## 下一段：完善中性数据与业务扩展

- [ ] **版本化业务属性。** 收敛带命名空间、类型、目标范围、产生者、方法版本及证据的属性 / 注释合同。来源标签、人工意见和插件结果可以共存，权限和搜索行为明确。
- [ ] **标注器与可验证证据。** 按统一规范登记标注器版本、专家参照、评测集、逐条输出与验证结果；提供追溯和查询，有验证依据的相关候选优先展示。验证方法与证据强度计算由模块扩展，材料登记不要求平台人工认证；见[研究与最小闭环](research/annotation-evidence-20260915.md)。
- [ ] **插件产物可组合。** 一个分类插件的确定版本被另一个统计插件消费；切换 renderer 读取已有结果；在分析上下文启停插件，Case 主 UI 保持单选。
- [ ] **切片有稳定引用。** 用户轮次、记录范围、因果关联与选择清单可精确读取；空集、未知归属和缺失正文都有正确表达。查询分页、逻辑切片、物理分片分别验收。
  - Case 验收暴露的下一步：按 Skill/API 检索；有覆盖说明的用户轮次统计；可直接处理固定选集的统计插件。现有运行级查询和逐条插件不能替代这些能力。
- [ ] **补采与长多轮协议贯通。** 同一份兼容性测试覆盖重复上报、乱序、压缩、并行和中断；原件保留，修正有依据，时间与用量不重复计算。

## 支线：官方证据强度检查插件

- [ ] **证据强度检查工具。** 作为普通官方插件读取证据包，依据公开、版本化的方法，输出证据强度评价、具体依据和可补充的材料；检查结果作为派生产物保存并可追溯。使用平台公共接口，由用户或 Agent 显式调用，不阻塞材料导入与登记。待核心协议收敛后独立推进，当前仅记录规划。

## 后续：回放与独立验证

- [ ] **先接一个可恢复的环境。** 固定输入、初态、工具版本和网络条件，回放产生新轨迹；初始化失败不记成模型失败。
- [ ] **逐种交付回放。** 明确复用录制结果、重执行动作、重新运行模型的差异；每种都有正确样例和故障恢复验收，不把历史回看或远程任务派发当作完成。
- [ ] **独立验证结果。** 同条件下已知正确 / 错误产物能被区分；验证报告引用新旧轨迹、环境和方法。执行完成与业务通过分别统计。

## 后续：训练出口与规模

- [ ] **训练样本发布。** 由指定 profile / 转换器核实证据要求，固定成员、源版本与转换结果；发布与训练分片各有清单及摘要。
- [ ] **训练消费记录。** 一个真实训练程序报告实际读取 / 使用范围和 step 或 checkpoint，重复回执可对账；下载与通知 ACK 都不自动代表训练消费。
- [ ] **存储和搜索扩展。** 先测大正文、批量导入、查询延迟、索引积压与恢复，再引入 S3 内容适配、物理分块 / 分区或分析读库；核心引用不随布局变化。
- [ ] **按瓶颈评估 Rust。** 现有合同和固定历史样本验证正确性、恢复行为和资源消耗，再决定替换范围。没有基准时不预设加速倍数。
