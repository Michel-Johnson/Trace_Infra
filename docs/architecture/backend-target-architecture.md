# 后端目标架构

状态：目标架构。Python核心阶段已完成001–020并按用户确认收尾，尚未更新生产部署；当前交付和后续边界见[阶段交付](../implementation/backend-core-stage-1.md)，逐项证据见[迭代记录](../implementation/backend-iterations.md)。依据为[Langfuse / Discover Traces 研究](../research/langfuse-traces-backend-architecture-20260912.md)与现有提交 a9492c9。业务生命周期仍以[训练轨迹基础设施](training-data-platform.md)为主设计；本文固定技术边界与实施顺序。

## 决策

继续使用 **FastAPI + 共享 Python 领域核心 + PostgreSQL + 独立 Worker**。增加不可变内容存储，以统一协议连接远程 Agent、回放环境、验收器与训练程序。Web、CLI、MCP 都是平台客户端。

初期不增加 API 到 Backend 的内部 RPC；Backend 是由 API 和官方 Worker 调用的模块。独立进程用来隔离交互请求与耗时工作，领域模块用来隔离职责。服务数量和语言不作为平台规模的替代指标。

## 工程与运行边界

| 单元 | 代码/协议责任 | 运行方式 |
|---|---|---|
| Web | 页面、查询交互、一个活动的 Case UI renderer | 独立静态 Web 镜像 |
| API | HTTP、服务身份、传输校验、错误与幂等入口 | FastAPI 进程，调用共享核心 |
| Backend | 版本/查询、产物/血缘、任务、回放验收、发布、消费 | 共享 Python 包；复用基础镜像 |
| Worker | 索引、官方分析、转换、调度与对账 | 独立进程，按资源池扩容 |
| PostgreSQL | 元数据、事务、任务/租约、发布/回执、初期查询投影 | 独立持久服务 |
| 内容存储 | 原始正文、附件、环境快照、详细报告、训练分片 | 受控 S3 兼容服务；开发可用目录适配 |
| Plugin | Manifest、计算/渲染能力及类型化产物 | 按实现由 Web、Worker 或远程 runtime 承载 |
| 远程执行器 | 模型、环境操作、验收或训练 | 独立部署，以受限 API 领取输入及回写 |
| SDK / CLI / MCP / skills | 发现能力、读取数据、显式申请操作的客户端适配与指导 | 同协议；不各自维护第二套业务状态 |

当前镜像关系与 systemd 现状见[服务边界](service-boundaries.md)。内容存储及完整训练生命周期属于待实现项，不因出现于此表就成为现有生产能力。

建议逐步按 traces/catalog、query/selections、artifacts/lineage、invocations、replay/validation、datasets、consumption 组织领域代码。保留一个仓库和兼容层，不要求一次迁移所有文件。远程 runtime 的 URL、部署健康与凭据引用独立于不可变 PluginVersion。

## 数据权威

PostgreSQL 决定“资源是哪一版、谁能读写、任务在哪个 attempt、哪份数据被发布、训练端确认过哪些使用”。对象存储保存经摘要校验的完整内容。查询投影可以重建、裁剪和更换数据库，不能取代完整证据、冻结成员或消费账本。

查询允许 latest；分析、回放、验收、转换与发布必须固定输入版本及摘要。所有派生输出保存上游引用。补采生成新 revision，重新执行生成新 run，分析不覆盖原轨迹。旧导入和 digest 不重写。

接入先完成内容上传与摘要校验，再在数据库事务登记 ready 引用及待处理工作。使用同库持久任务队列；需要跨系统可靠通知时加事务 outbox。索引完成后才推进对应水位，失败记录可查、可重试。sealed 仅代表该 revision 的成员固定，训练可用性由 profile 再判断。

## 对 Agent 的合同

一套可校验的资源 Schema 和应用服务，分别适配 HTTP、SDK、CLI 与 MCP。MCP 可以使用紧凑参数和领域工具，不必机械暴露所有 HTTP 操作；最终权限、版本与副作用仍由相同服务端规则决定。skills 只提供流程指导。

一期优先提供：

- 字段、过滤、聚合与权限的能力发现。
- 有界查询、稀疏字段、稳定分页、范围及索引水位。
- 已有分析/产物的精确版本查询与内容切片。
- SelectionSnapshot：持久保存确定的成员、版本与摘要。
- 显式计算请求及任务状态读取。

读取不创建分析，也不登记训练消费。服务身份区分读取、计算、回放、发布和确认消费；项目范围由鉴权上下文确定。未知、未适用、截断、缺证据与确实为零分别表达。

## 插件与执行

通用执行对象是 Invocation，输入为固定引用集合，输出可以有多个独立的 typed Artifact。保留 attempt、租约、取消和幂等结果提交；旧评测和插件任务已改用明确的仓库表绑定，共享事务生命周期，不再用正则改写SQL文本；历史表和对外接口保留。

先接通一条固定短链：选集 → Base 分类 → 问题统计/验收 → 样本转换。插件只通过声明的能力读取证据和提交结果，不直接改发布资格或消费表。数据要求由插件声明，是否达到训练发布条件由核心执行版本化政策。

官方可信计算在独立 Worker 中执行；外部 Agent、环境回放和任意代码由各自 runtime 承载。普通子进程不等于沙箱。 租约和 attempt 只能约束结果回写；外部动作还需稳定 operation ID、执行端幂等或对账。动作结果不明时保留 outcome_unknown，避免盲目重试造成重复副作用。UI 主 renderer 同时只启用一个，后端分析产物可以多个共存；换视图不重算。

## 首个闭环的验收

| 增量 | 必须证明 |
|---|---|
| 版本与内容 | 旧版不可变、完整原件可读、重传幂等、缺口不静默消失 |
| 查询与选集 | Agent 可查询/聚合/读报告；查询不计算；冻结成员不漂移 |
| 通用执行 | 两个插件串联，绑定准确上游版本；重复提交不重复产物 |
| 回放与验收 | 一种初态可恢复的环境产生新轨迹；正确/错误产物被独立区分 |
| 发布与消费 | 一种训练 profile 与真实消费端；下载不算训练；回执可重试对账；checkpoint 可反查 |

真实训练确认是训练端报告并附证据的事实，不以 ACK 推断样本对权重的因果效果。消费区分任务、attempt、epoch/step；同一数据可以合法复用。发布后修复、撤销资格或纠正回执保留历史关系。

## 扩展决策

- **ClickHouse：**待初期投影与索引优化后，统计扫描仍不能满足实测查询目标，再作为可重建分析读库接入。
- **接入服务独立化：**待批量入库持续干扰交互流量时，先拆进程/扩副本，再决定服务边界。
- **工作流引擎：**待跨日等待、分支、补偿、人工介入使现有执行调度复杂时验证；不能出现两个争夺执行状态权威的引擎。
- **消息流平台：**待多个独立消费者需要持久流重放且有真实吞吐需求时评估。
- **Rust：**按已确认的实施顺序，先完成 Python 的完整服务闭环，再以同一合同、固定历史样本和相同 PostgreSQL 事务语义验证 Rust 实现。对比能力、正确性、恢复行为与实测资源消耗；不能只测试健康接口或客户端封装。插件和远程 Agent 保留语言自由。切换需通过能力对齐，不预设速度提升倍数。
- **Go / Java 或更多微服务：**仅对已有测量的热点或必须独立发布的边界重评，不整体推倒已验证协议与数据。

当前无生产压测结果，不承诺吞吐上限。先以长多轮、大正文、乱序补采、并行动作和 Worker 故障做纵向验收，再依据队列积压、查询延迟、扫描字节、存储增长与恢复时间作扩容决定。

## 迁移约束

新资源采用追加迁移，旧协议通过适配层继续读取；不更改历史原文和 digest。新合同必须有实际客户端和语义验收，避免只扩张离线 Schema。

本决策未引入运行时依赖。后续引入组件继续遵守仓库的七天发布冷却期、固定锁文件与制品核验要求。Langfuse 可作为来源适配或方法参考，完整 fork 不是默认后端方案；Discover Traces 的生产技术栈仍未公开，不能作为具体组件已被验证的依据。
