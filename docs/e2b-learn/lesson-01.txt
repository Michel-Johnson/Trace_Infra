E2B 第 01 课：先认清四个对象

E2B 用 sandbox 跑环境。pause 停同一台，snapshot 留检查点，fork 从检查点立刻开多台。

这一课只讲 E2B 对外暴露的四个对象，以及它们和我们说的环境 state 怎么对应。E2B 是一套给 agent 用的隔离 Linux 执行环境。它不记录模型调用，也不保存 span。

下面名称第一次出现时写出全称。操作行为来自 E2B 文档。和我们系统的对应关系是推断，文中会分开写。

sandbox 是一台正在运行的 Linux 虚拟机实例。你在里面执行命令、读写文件。底层用 Firecracker，即 Virtual Machine Monitor，微型虚拟机监视器。

template 是声明式起始镜像，规定装哪些软件、用哪份根文件系统。同一份 template 每次 Sandbox.create() 得到同一类起始环境。它不是某次运行中途的状态。

snapshot 是对正在运行的 sandbox 做一次时刻捕获，包含文件系统和内存。原 sandbox 会短暂暂停，完成后继续跑。你得到一个可反复使用的 snapshot_id。

fork 是一次调用：先做 snapshot，再立刻启动最多 100 台新 sandbox。新机器各有自己的 ID 和超时。这次用掉的内部 snapshot 不作为以后还能单独引用的检查点留给你。

pause 不是 snapshot，fork 也不是留下检查点。pause() 和 connect() 作用在同一台机器上，一对一停掉再继续，你拿到的还是同一个 sandbox_id。

create_snapshot() 会让原机器短暂暂停后继续跑。关系是一对多。你拿到可长期使用的 snapshot_id。

fork(count=N) 同样让原机器短暂暂停后继续跑。关系是一对多，并且立刻启动。你拿到 N 台正在跑的新 sandbox。

pause 默认把内存一起保存。若 keep_memory=False，只留磁盘，下次启动会重新引导，内存里的进程没有了。

事实是：一份 snapshot 可以启动很多台新 sandbox；fork 在一次调用里完成捕获和启动。

推断如下。我们说的环境 state 对应 snapshot。在同一环境下做 N 次模型实验对应 fork，或 create_snapshot() 之后多次 Sandbox.create(snapshot_id)。需要以后还能回到同一点，用 snapshot，不要只用 fork。

调用顺序可以写成下面这样。这段按官方 SDK 写法整理，用来讲顺序，不是本环境里跑过的结果。

from e2b import Sandbox

sandbox = Sandbox.create()
sandbox.files.write("/home/user/state.txt", "before experiment")

snapshot = sandbox.create_snapshot()

now = sandbox.fork(count=3)
for child in now:
    if isinstance(child, Sandbox):
        child.commands.run("cat /home/user/state.txt")

later = Sandbox.create(snapshot.snapshot_id)

snapshot 和 fork 会暂时断开 WebSocket、伪终端、命令流，客户端必须重连。E2B 不保存你送给模型的 prompt，也不保存模型输出。轨迹采集要另做。

来源：https://docs.e2b.dev/docs 、https://docs.e2b.dev/sandbox/persistence 、https://docs.e2b.dev/sandbox/snapshots 、https://docs.e2b.dev/sandbox/fork 。底层拆分见 https://github.com/e2b-dev/infra/blob/main/docs/ARCHITECTURE.md ，下一课再展开。

总结：要留可回放的环境点，用 snapshot。要马上开多台做实验，用 fork。pause 只停同一台，不能当检查点用。
