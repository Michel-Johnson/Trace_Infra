E2B · 第 01 课

先认清四个对象：sandbox、template、snapshot、fork

E2B 用 sandbox 跑环境；pause 停同一台，snapshot 留检查点，fork 从检查点立刻开多台。

这一课只解决什么

E2B 是一套给 agent 用的隔离 Linux 执行环境。它不记录模型调用，也不保存 span。本课只讲它对外暴露的四个对象，以及它们和我们说的环境 state 怎么对应。

下面名称第一次出现时写出全称。事实来自 E2B 文档；和我们系统的对应关系是推断，文中会分开写。

四个对象

sandbox

一台正在运行的 Linux 虚拟机实例。你在里面执行命令、读写文件。底层用 Firecracker = Virtual Machine Monitor = 微型虚拟机监视器。

template

声明式起始镜像：装哪些软件、用哪份根文件系统。同一份 template 每次 Sandbox.create() 得到同一类起始环境，不是某次运行中途的状态。

snapshot

对正在运行的 sandbox 做一次时刻捕获，包含文件系统和内存。原 sandbox 会短暂暂停，完成后继续跑。得到一个可反复使用的 snapshot_id。

fork

一次调用：先 snapshot，再立刻启动最多 100 台新 sandbox。新机器各有自己的 ID 和超时。这次用掉的内部 snapshot 不作为以后还能单独引用的检查点留给你。

三种操作不要混用

pause 不是 snapshot。fork 也不是留下检查点。差别如下。

操作 原 sandbox 关系 你拿到什么
pause() / connect() 停掉，之后再继续 一对一，还是同一台 同一个 sandbox_id
create_snapshot() 短暂暂停后继续跑 一对多 可长期使用的 snapshot_id
fork(count=N) 短暂暂停后继续跑 一对多，立刻启动 N 台正在跑的新 sandbox

pause 默认把内存一起保存。若 keep_memory=False，只留磁盘，下次启动会重新引导，内存里的进程没有了。

和我们要的实验怎么对上

事实：一份 snapshot 可以启动很多台新 sandbox；fork 在一次调用里完成「捕获 + 启动」。

推断：我们说的环境 state 对应 snapshot；在同一环境下做 N 次模型实验对应 fork，或 create_snapshot() 之后多次 Sandbox.create(snapshot_id)。需要以后还能回到同一点，用 snapshot，不要只用 fork。

from e2b import Sandbox

sandbox = Sandbox.create()
sandbox.files.write("/home/user/state.txt", "before experiment")

# 留下以后还能用的检查点
snapshot = sandbox.create_snapshot()

# 现在立刻开三台，互不影响
now = sandbox.fork(count=3)
for child in now:
    if isinstance(child, Sandbox):
        child.commands.run("cat /home/user/state.txt")

# 以后还可以再开
later = Sandbox.create(snapshot.snapshot_id)

这段代码按官方 SDK 写法整理，用来讲调用顺序，不是本环境里跑过的结果。

E2B 明确不管的事

snapshot 和 fork 会暂时断开 WebSocket、伪终端、命令流，客户端必须重连。它不保存你送给模型的 prompt，也不保存模型输出。轨迹采集要另做，或以后对照 Langfuse = LLM 观测平台。
