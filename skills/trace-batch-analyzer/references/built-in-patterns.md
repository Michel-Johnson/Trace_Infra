# 批量判定与复核

以下是取证与展示的候选模式，不是新评分规则。仅执行 Approved Spec 明确的指标、分组和阈值；四方面未获批的语义判断保持 unknown。

## 结果质量

逐单位连接用户目标、验收点与独立产物/终态，统计可验收、通过、失败和缺验收证据。按任务类型或 Skill 版本分组时，先展示各组规模和覆盖；最终答复或提交动作不能单独当作成功。

## 执行过程

用固定的历史 Skill 版本和决策时可见 Context 核查规定步骤、首次偏离、遗漏、循环以及修复后的状态。报告问题发生在多少个分析单位，另可统计事件数；同一 Trace 多次事件不能膨胀为多条失败 Trace。缺历史版本或可见性证据时标 unknown。

## 工具调用

按稳定调用身份区分 proposal、真正执行、失败、重试候选及执行后的处理。分开统计选型、参数、工具/环境故障、Agent 对返回的误用；同名调用、正文提及或时间相邻不能证明调用、重试或因果。工具调用次数可以大于 Trace 数，比例分母须标明是调用、尝试还是 Trace。

## 效率与稳定性

用已采集的 duration、Token 和 error 做分布与缺失覆盖；在确认重复任务及身份关系后统计重试/恢复。p50/p95 只有在有效单位、时间口径和总体一致时比较；缺失不能按 0 处理。没有 Approved Spec 的基线不判定“异常耗时”。

## 聚合与复核

每方面先做逐单位判定，再汇总 `pass`、`issue`、`unknown`、`not_applicable`、未处理数、可判定分母和覆盖率。优先观察重复问题、严重个案、分组差异与可能相反的证据；按通过、问题、边界、未知抽样复核，必要时用 `spans/window` 展开争议步骤。规则失准时停止本轮并反馈 Eval Designer，不在同一结果中混用新旧判定。

观察性 Cohort 只能描述差异及任务、模型、环境、权限等剩余混杂，不能把 Skill 有无直接写成效果归因。搜索仅作候选召回，不能据命中数统计问题率。
